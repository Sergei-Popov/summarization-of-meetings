# Структурная редактура PRD

Этот документ существует, чтобы помочь UX-дизайнеру, архитектору и автору историй быстро понять обещание продукта, границы MVP, критерии успеха и обязательные требования к локальному приложению для суммаризации встреч.

**Выбранная модель:** Strategic/Context (Pyramid). PRD должен идти сверху вниз: продуктовое обещание и статус → аудитория и границы → критерии успеха → подробные требования → ограничения и архитектурная передача.

Исходный объём по `word_metrics.py`: **3 494 слова**. Самые крупные смысловые блоки: функциональные требования — основная часть документа; §6 — 289 слов; §9 — 246 слов; §10 — 179 слов; §5.4 — 178 слов; §3 — 161 слово; §1 — 130 слов; §5.1 — 130 слов; §11 — 101 слово.

## Сводка сокращения

- Рекомендаций: **9** — 3 MOVE, 2 MERGE, 2 CONDENSE и 2 PRESERVE; первая MOVE-рекомендация включает только перестановку разделов.
- Если принять все изменения, PRD сократится примерно на **295 слов**, или **8,4%** от исходных 3 494 слов, до примерно **3 199 слов**.
- Из этой суммы **101 слово** переносится в `addendum.md`, поэтому чистое сокращение комплекта артефактов составит около **194 слов**; содержательные решения не теряются.
- Целевой объём не задан. Для hobby/solo PRD предложенная структура повышает плотность без агрессивного урезания требований.
- Компромиссы для восприятия: не предлагается сокращать глоссарий, путь пользователя или обзор MVP, потому что они обеспечивают навигацию и понимание для человеческой аудитории. Единственная заметная потеря в основном файле — видимый список истории D1–D15; аудит остаётся в `.memlog.md`, а утверждённые решения — в соответствующих требованиях.
