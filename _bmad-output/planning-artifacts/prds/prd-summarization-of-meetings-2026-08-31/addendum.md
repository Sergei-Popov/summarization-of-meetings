# Техническое приложение к PRD

Следующие решения служат исходными данными для проектирования, а не утверждённой архитектурой. Обязательные ограничения можно изменять только через обновление PRD; предварительные решения подлежат проверке в архитектуре.

## Обязательные ограничения

- Исходная запись рабочей встречи поступает в приложение в видеоформате.
- Для транскрибации и суммаризации можно независимо выбирать внешний OpenAI-совместимый провайдер или локальную модель.
- Приложение локальное и однопользовательское; исходный код публикуется для самостоятельной установки другими людьми.
- Постоянные метаданные, расшифровки, саммари, настройки и состояние фоновых заданий хранятся в локальной базе данных. Крупные видео- и аудиофайлы хранятся в управляемой локальной файловой области, а база данных содержит ссылки и метаданные.
- Автоматический переход с локальной модели на внешний сервис запрещён, поскольку он нарушил бы обещание приватности.
- Саммари должно содержать ссылки на сегменты расшифровки и соответствующие таймкоды. Это снижает риск неконтролируемых выводов модели и ускоряет ручную проверку.

## Предварительные архитектурные решения

- Основной способ распространения MVP — Docker Compose; по умолчанию веб-интерфейс доступен только с локального компьютера через loopback-интерфейс.
- Для транскрибации и суммаризации профили внешних движков хранят отдельные базовые URL, API-ключи и идентификаторы моделей.
- Для внешней транскрибации приложение локально извлекает аудио, чтобы не отправлять видеодорожку без необходимости.
- Для локального режима предусмотрено по одному поддерживаемому способу запуска ASR- и LLM-моделей. Конкретные модели и среды выполнения выбираются на этапе проектирования архитектуры после проверки лицензий и тестирования производительности на компьютере с 16 ГБ оперативной памяти.
- Длительная обработка представлена сохраняемым многоэтапным фоновым заданием с возможностью повторить отдельный этап.
- Диаризация полезна, но её качество зависит от выбранного движка. MVP сохраняет метки спикеров и позволяет их редактировать, если движок предоставляет такие метки; успешная обработка не требует диаризации.
- Исходное видео по умолчанию сохраняется для повторной обработки. Пользователь видит, сколько места занимает файл, и может удалить его, сохранив текстовые результаты.
- Исходный код планируется выпустить под лицензией Apache License 2.0. Перед публикацией необходимо проверить совместимость лицензий всех включённых моделей и зависимостей.

## Архитектурная передача: открытые решения

Эти вопросы не блокируют PRD. Владелец каждого решения — будущий автор архитектуры:

1. Какие конкретные локальные модели и среды выполнения удовлетворяют FR-6 и аппаратным требованиям §7.3 на трёх целевых ОС? **Пересмотр:** до проектирования локального контура обработки.
2. Каким способом реализуются инварианты защиты секретов из §7.1 при разных вариантах локального запуска, включая контейнерный? **Пересмотр:** до реализации хранения Профилей обработки.
3. Как обеспечиваются миграции локальной базы данных, резервное копирование и восстановление без потери Исходных видео? **Пересмотр:** до фиксации схемы данных и механизма обновления.
4. Какая реализация поиска обеспечивает NFR-2 без передачи данных внешнему сервису? **Пересмотр:** до реализации библиотеки Встреч.

## Исследовательский контекст

Обзор восьми актуальных проектов с открытым исходным кодом и смежных продуктов находится в [research-landscape.md](research-landscape.md). Ближайший аналог — Scriberr; на рынке не хватает простого локального веб-сценария (local-first) с независимой настройкой OpenAI-совместимых ASR- и LLM-движков. Типичные риски: неясные границы приватности, нестабильность длительных заданий, качество диаризации, аппаратные требования, политика хранения и отсутствие проверяемых ссылок из саммари на расшифровку.
