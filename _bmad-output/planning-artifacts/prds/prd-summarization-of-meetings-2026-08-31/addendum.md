# Техническое приложение к PRD

Документ содержит исходные данные для проектирования, но не утверждает архитектуру. Обязательные ограничения изменяются только через обновление PRD; предварительные решения необходимо проверить при проектировании архитектуры.

## Обязательные ограничения

- Исходная запись рабочей встречи поступает в приложение как один аудио- или видеофайл; прямой импорт аудио является обязательной возможностью MVP.
- Для транскрибации и суммаризации можно независимо выбирать внешний OpenAI-совместимый провайдер или локальную модель.
- Приложение локальное и однопользовательское; исходный код публикуется для самостоятельной установки другими людьми.
- Локальная база данных хранит постоянные метаданные — Теги, данные Справочника участников и связи с Внешними задачами, — а также Расшифровки, Саммари, настройки и состояния фоновых заданий. Управляемая локальная файловая область хранит крупные Исходные записи и производные медиафайлы; база данных хранит их ссылки и метаданные.
- Приложение хранит только URL и структурированный номер Внешней задачи. MVP не обращается к API трекера, не создаёт задачи и не синхронизирует их атрибуты.
- Автоматический переход с локальной модели на внешний сервис запрещён, поскольку он нарушил бы обещание приватности.
- Саммари должно содержать ссылки на сегменты расшифровки и соответствующие таймкоды. Это снижает риск неконтролируемых выводов модели и ускоряет ручную проверку.

## Предварительные архитектурные решения

- Основной способ распространения MVP — Docker Compose; по умолчанию веб-интерфейс доступен только с локального компьютера через loopback-интерфейс.
- Исходный код планируется выпустить под лицензией Apache License 2.0. Перед публикацией необходимо проверить совместимость лицензий всех включённых моделей и зависимостей.
- Профили обработки отдельно хранят базовые URL, API-ключи и идентификаторы моделей для внешних Движков транскрибации и суммаризации.
- Для внешней транскрибации приложение локально извлекает аудио из видео либо подготавливает прямой аудиофайл, чтобы не отправлять видеодорожку без необходимости.
- MVP предусматривает по одному поддерживаемому способу запуска локальных ASR- и LLM-моделей. Конкретные модели и среды выполнения выбирают при проектировании архитектуры после проверки лицензий и производительности на компьютере с 16 ГБ оперативной памяти.
- Приложение представляет длительную обработку как сохраняемое многоэтапное фоновое задание и позволяет повторить отдельный этап.
- Диаризация полезна, но её качество зависит от выбранного движка. MVP сохраняет метки спикеров и позволяет их редактировать, если движок предоставляет такие метки; успешная обработка не требует диаризации.
- Приложение хранит Встречу и Исходную запись без автоматического срока удаления, чтобы пользователь мог проверить результат или повторить обработку. Пользователь видит размер файла и может явно удалить его, сохранив текстовые результаты.

## Открытые вопросы

### Архитектура

Эти вопросы не блокируют PRD. За каждое решение отвечает будущий автор архитектуры:

1. Какие конкретные локальные модели и среды выполнения удовлетворяют FR-6 и аппаратным требованиям §7.3 на трёх целевых ОС? **Пересмотр:** до проектирования локального контура обработки.
2. Как реализовать инварианты защиты секретов из §7.1 при разных вариантах локального запуска, включая контейнерный? **Пересмотр:** до реализации хранения Профилей обработки.
3. Как обеспечить миграции локальной базы данных, резервное копирование и восстановление без потери Исходных записей, Тегов, Справочника участников и связей с Внешними задачами? **Пересмотр:** до фиксации схемы данных и механизма обновления.
4. Как совместить полнотекстовый поиск с отдельным structured exact/prefix-индексом номера Внешней задачи без передачи данных внешнему сервису? **Пересмотр:** до реализации библиотеки Встреч.

### QA и тест-дизайн

До оценки качества на корпусе выпуска зафиксируйте протокол расчёта precision, recall и корректности ссылок для решений и задач. Определите единицу сопоставления, правила для неоднозначных эталонов и способ агрегации результатов. Протокол не меняет пороги PRD, а делает их воспроизводимыми.

## Исследовательский контекст

Обзор восьми актуальных проектов с открытым исходным кодом и смежных продуктов см. в [research-landscape.md](research-landscape.md). Ближайший аналог — Scriberr. На рынке не хватает простого локального веб-сценария (local-first) с независимой настройкой OpenAI-совместимых ASR- и LLM-движков. К типичным рискам относятся неясные границы приватности, нестабильность длительных заданий, качество диаризации, аппаратные требования, политика хранения и отсутствие проверяемых ссылок из Саммари на Расшифровку.
