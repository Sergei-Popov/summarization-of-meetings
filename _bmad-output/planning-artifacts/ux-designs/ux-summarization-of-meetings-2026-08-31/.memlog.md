- (event) Пользователь подтвердил источники: PRD, addendum, research-landscape и ARCHITECTURE-SPINE.
- (decision) Видение пользователя: открыть приложение, загрузить запись встречи в видео- или аудиоформате; фактический основной формат — видео, потому что записи встреч обычно доступны как видео; получить краткую сводку и важные детали того, что было оговорено на встрече.
- (decision) Библиотека должна показывать все ранее загруженные владельцем встречи. Для каждой встречи нужна полноценная отдельная страница: содержание разговора и история кратких сводок. В библиотеке нужны фильтры по датам и тематикам. Тематические теги должны проставляться автоматически и допускать ручное изменение. Встречу можно вручную связать с задачей и сохранить ссылку на эту задачу.
- (assumption) Ответ «все верно» интерпретирован так: библиотека представляет историю встреч, у каждой встречи хранится одна актуальная краткая сводка; история версий сводки одной встречи не требуется. Это сохраняет действующий MVP-контракт FR-18.
- (event) Выбран coaching path по наблюдаемому пошаговому режиму диалога; пользователь может сменить режим.
- (decision) Уточнение UJ-1 и его кульминации: после завершения анализа видео или аудио Сергей открывает результат и видит общую текстовую сводку, а отдельно — полный перечень всех озвученных договорённостей по пунктам. Для каждой договорённости должны отображаться упомянутые на встрече сроки, даты и иные конкретные детали; важные договорённости должны быть различимы среди полного перечня. Кульминация пути — Сергей видит, о чём именно договорились, без повторного просмотра записи.
- (decision) Встречи и их исходные записи хранятся бессрочно, пока владелец сам явно не удалит их. Автоматический срок хранения не применяется.
- (decision) На полноценной странице Встречи должен быть встроенный рабочий плеер исходной записи: видео- или аудиоплеер в зависимости от формата. Владелец запускает и просматривает/прослушивает запись прямо в приложении; существующее требование перехода по таймкоду связывает элементы результата с плеером.
- (override) Прямой импорт аудиофайлов добавляется к MVP наряду с видео. Это расширяет исходные PRD FR-1 и scope 3.1, где создание Встречи было ограничено одним видеофайлом; продуктовые лимиты и поддерживаемые аудиоформаты ещё не определены.
- (decision) Архивный сценарий: Сергей ищет ранее загруженную Встречу по дате, номеру связанной задачи из внешней системы или тегам. У связи с задачей есть внешний URL; номер задачи присутствует в этой ссылке и должен быть доступен как поисковая зацепка. После нахождения Сергей открывает страницу Встречи и восстанавливает содержание и договорённости.
- (decision) Теги Встречи могут создаваться владельцем вручную или назначаться автоматически; библиотека поддерживает поиск/фильтрацию по тегам.
- (decision) Нужен локальный мини-справочник участников Встреч. Владелец наполняет его и выбирает для каждой Встречи одного или нескольких участников. Участники являются метаданными Встречи, а не пользователями приложения или ролями доступа.
- (decision) Справочник участников и выбор участников для Встречи не связываются с метками спикеров, репликами или Расшифровкой. Это независимые архивные метаданные: кто присутствовал на Встрече. Переименование распознанных спикеров остаётся отдельной возможностью.
- (event) Пользователь делегировал визуальный вкус и цвет, попросил автономно пройти оставшиеся UX-решения без вопросов и остановиться на готовых референсах для одобрения.
- (assumption) Stakes: локальный внутренний рабочий инструмент одного владельца; consumer growth-механики, регулируемый workflow и командные роли не требуются.
- (assumption) Основной form factor — desktop/laptop responsive web в локальном браузере. Ширина ниже desktop поддерживает чтение и простые действия, но mobile-native app и полноценный мобильный workflow вне MVP.
- (assumption) Язык интерфейса первой версии — русский; язык Саммари остаётся настраиваемым по PRD. Тексты короткие, прямые, нейтрально-деловые, без маркетингового восторга.
- (assumption) Accessibility floor — WCAG 2.2 AA, полная клавиатурная доступность, видимый focus, labels, screen-reader semantics, смысл не только цветом, reduced motion; primary controls не меньше 44 CSS px.
- (assumption) Обработка может занимать долгое время: прогресс и восстановимые ошибки показываются внутри приложения; push, email и системные уведомления вне scope. Motion функциональный и сдержанный.
- (assumption) Темы/теги автоматически создаются после успешного Саммари, сразу видимы и редактируемы владельцем. Фильтры библиотеки включают дату, тег, номер внешней задачи и участника.
- (assumption) При добавлении внешней ссылки приложение извлекает номер задачи из URL для отображения и поиска; при невозможности распознать номер сохраняет ссылку и предлагает ручное поле номера без подключения к внешней системе.
- (assumption) Визуальная отправная точка: спокойный профессиональный рабочий инструмент, content-first, средней/высокой плотности, с отчётливой иерархией сводка → договорённости → подтверждение; без игровых элементов, градиентного декора и навязчивой анимации. Светлая тема по умолчанию, тёмная следует системной настройке.
- (assumption) Иерархия страницы завершённой Встречи: общая сводка и полный список договорённостей читаются раньше Расшифровки; плеер остаётся доступным при проверке подтверждений и переходах по таймкодам. На desktop допустима двухзонная композиция, на узкой ширине зоны складываются последовательно.
- (assumption) Для черновых спайнов и key-screen mocks выбран визуальный вариант 01 «Спокойное рабочее пространство» из .working/design-directions-1.html: светлый профессиональный content-first интерфейс средней/высокой плотности, teal accent, мягкие границы, две зоны страницы встречи. Варианты 02 и 03 остаются альтернативами до пользовательского одобрения.
- (event) Подготовлены draft-референсы для пользовательского одобрения: design-directions-1.html, ia-2026-08-31.excalidraw, key-library.html, key-meeting-detail.html, key-processing.html; DESIGN.md и EXPERIENCE.md заполнены со статусом draft. Рекомендуется направление 01, подтверждение пользователя ожидается.
- (decision) Пользователь одобрил визуальные референсы без замечаний и поручил продолжить автономно. Направление 01 «Спокойное рабочее пространство», продуктовый label «Контекст», library/meeting-detail/processing compositions и связанные делегированные визуальные assumptions приняты.
- (decision) Mock coverage подтверждено: library/search, meeting detail и processing имеют HTML-моки; import, participants, profiles, settings/diagnostics и overlays остаются spine-only. Дополнительные визуальные референсы не запрошены.

Production UI должен собираться из готовых компонентов Ant Design и их штатного API темизации; собственный CSS не используется для повторной реализации доступных компонентов и допускается только как минимальный layout/product-specific delta, который нельзя выразить через theme tokens, component props или composition. HTML-моки остаются только визуальными референсами, не исходным кодом реализации.
